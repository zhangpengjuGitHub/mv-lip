## 三、选型结论

**主选 MuseTalk 1.5**，理由：

1. 唯一同时满足「快到能跑全曲」+「许可干净可商用」+「输入形式正好是视频+音频」三项。
2. `bbox_shift` 是唱歌场景唯一现成的张嘴幅度旋钮，长音「啊——」的大开口有救。
3. 官方明确推荐先用 I2V 生成有动作的视频再对口型，与本项目的「先剪视频」链路天然吻合。
4. 代码 MIT + 权重可商用，Wav2Lip 因训练集 LRS2 明确禁止商用，直接排除。

**备选 LatentSync**：画质更锐、时间一致性更好，但扩散模型慢一个量级，且权重商用许可需自行核实。若 MuseTalk 画质不达标再上。

**备选 ComfyUI-LatentSyncWrapper**：如果不想单独装环境，可以挂进现有 Kaggle 的 ComfyUI（8188 端口已跑 WanVideoWrapper）。但节点成熟度不如官方脚本。

**明确排除 Wav2Lip 系**：许可不可商用 + 96×96 糊。仅保留作为「同步是否准确」的对照基准。

## 四、依赖与部署注意（MuseTalk）

- 官方推荐 Python ≥3.10、CUDA 11.7、PyTorch 2.0.1；依赖 MMLab 全家桶（`openmim / mmengine / mmcv / mmdet / mmpose`），**这是部署最容易踩坑的地方**，建议独立 venv，别和 ComfyUI 装一起。
- 权重清单：`musetalkV15/unet.pth` + `musetalk.json`、`sd-vae`、`whisper`（tiny）、`dwpose`、`face-parse-bisent`、`resnet18`、`syncnet`。官方提供 `download_weights.sh` / `.bat`。
- 需要 ffmpeg-static，Linux 下用 `FFMPEG_PATH` 指定。
- 推理命令（v1.5）：
  ```bash
  sh inference.sh v1.5 normal
  # 或
  python -m scripts.inference --inference_config configs/inference/test.yaml \
      --result_dir results/test \
      --unet_model_path models/musetalkV15/unet.pth \
      --unet_config models/musetalkV15/musetalk.json --version v15
  ```
- 配置只有两个核心字段：`video_path`、`audio_path`；`bbox_shift` 作为命令行参数传入。

## 五、本项目的额外风险（来自项目记忆）

- **动画角色五官识别弱**：DWPose / face-parse / S3FD 都是真人训练的。水墨**厚涂写实风**比扁平赛璐璐更容易被识别（当初定这个美术风格顺带解了技术坑），但仍须先用纯说话音频做 5 秒五官预检。
- **必须喂干声**：S2V 遇带伴奏音频口型明显漂移，两条独立实测一致。干声只作驱动，成片叠回完整混音。
- **静音段测试**：纯伴奏间奏时嘴还在动 = 人声没分离干净。
